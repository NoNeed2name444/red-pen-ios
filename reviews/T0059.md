## Correctness

Every way the Worker reaches the Anthropic URL:
- The only fetch is in askAnthropic (`ai.js:535`), and its only caller is complete() (`ai.js:424`).
- complete() is called from four places:
  - chat (`ai.js:149` for the terms prompt, `:156` for the answer). The route comes from routeFor, which is gated at `:1258`. Jobs reach chat at `jobs.js:525` and `:639`, and the app at `worker.js:190-191`. chat refuses an owner's pinned Claude (`ai.js:107-108`).
  - askModel (`ai.js:231`), with a pinned gemini, workers-ai or bench source only. `claude:` goes to the voter (`:220`), and anything else is refused (`:221`).
  - askClaudeVoter (`ai.js:261`): owner only (`:251`, `accuracy.js:272`), held and counted under "claude:owner" within CLAUDE_MONTHLY_USD (`ai.js:252-257`), with `canPay: false`, so the lane's wallet is never touched.
- No other server file names api.anthropic.com.

The hold's arithmetic:
- worstCase is a max over models (`ai.js:1065-1069`). The new hold (`ai.js:401-407`) is a max over per-model worstCase calls, so for every non-Claude model it equals f0d33dea's.
- Claude's term is `input × price.in + anthropicMaxTokens(maxTokens) × price.out`, which is exactly the max_tokens sent. That bounds Claude's billed output, thinking included.
- Above 4,000 reply tokens (jobs go up to 8,000), Claude's term, `min(m + 4,000, 16,000)`, is below the old `2m`. The hold there is lower than on f0d33dea, but it is still Claude's exact ceiling, as step 2 asked.

With PRO_PAYS on, routing is unchanged. The only difference is that hold.

The voter keeps its own hold expression (`ai.js:255`, `maxTokens + 4,000`), which is never below what is sent. A4 requires it to stay as it is, so this is not a second source for the lane's figure.
